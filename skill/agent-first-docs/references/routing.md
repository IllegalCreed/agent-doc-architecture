# 路由：让 Agent 只读该读的

入口文件只做路由，不做百科全书。Agent 无跨会话记忆、上下文有限，所以每次从入口进来，必须在几秒内知道「这件事先读哪一份」。

## 四层

| 层 | 内容 | 何时读 | 约束 |
|---|---|---|---|
| L0 常驻 | 入口文件：硬约定 + 路由表 | 每次会话自动加载 | 必须短 |
| L1 按工作类型 | 规范（开发 / 测试 / 数据库 / 封板 / 部署…） | 开工前按路由表只读一份 | 通用层 + 项目层 |
| L2 按模块 / 变更 | 变更文档、长期专题、交接文档 | 进入该模块时 | 有状态、有替代关系 |
| L3 证据 | 测试报告、审计、事故记录 | 需要证据时下钻 | 不承担入口职责 |

用户手册、更新日志、交接说明是**交付物**：读者是业务用户 / 运维，不进这套路由；路由表里只登记「何时必须更新它」。

## 入口文件骨架

```markdown
# AGENTS.md

## L0 硬约定
<每条：规则 + 一句理由 + 链接。完整实案放 L1/L2，这里只留链接>

## 操作 → 必读规范
| 操作 | 必读规范 | 一句话要点 |
|---|---|---|
| 新建 / 修改 docs 下任何文档 | [documentation-model.md](docs/handbook/engineering/documentation-model.md) | 先复制模板、禁止仿写上一份；提交前跑 doc-lint，0 ERROR；取号用 next-id |
| 写 / 改 / 审查任何测试 | [project-testing.md](docs/testing/guides/project-testing.md) | 先按「工作类型 → 测试层级」选层 |
| 封板 / 出包 / 打 tag | [release-process.md](docs/handbook/engineering/release-process.md) | 全量定义以该文件为准；封板前 doc-lint --release 0 ERROR |
| 数据库结构变更 | [database-changes.md](docs/handbook/database/database-changes.md) | 改结构必写增量脚本 |
| 代码审查 | 该变更的 handoff 审核清单 | 结论必须带「路径:行号」证据 |

**必读规范列写成 Markdown 链接**：`doc-lint` 的 `LINK-ENTRY` 只检查链接，裸路径文本指向了不存在的文件也不会报错。

**分层阅读原则**：L0 始终生效；L1 开工前只读路由表对应的一行；L2 进入模块时再读。不要为一件事通读全库，也不要没读 L1 就凭印象开工。
```

### 路由表怎么选行

- **收录**：高风险、低频、凭印象最容易出错的操作（封板、数据库变更、写测试、改核心引擎、代码审查）。
- **不收**：高频低风险的日常编码。
- **「一句话要点」列不能省**：Agent 即使没跳转，也拿到最关键的一条约束。
- 路由行指向的规范**还不存在**时，不要预建空文档：指向已有文档的某一节（如项目层文档模型的「封板清单」节），并在「一句话要点」写明「尚无专门文档」。
- 项目已有的根 `README.md` 只加一行指向 `docs/README.md`，不改其余；构建 / 运行 / 测试命令仍没有可核实来源时，入口文件写「尚无，待人确认」，**不编造**。
- 路由表是**按工作类型**索引，不是按目录；Agent 知道自己要干什么，但不知道文档放在哪。

## 每一跳都声明下一跳

- 文档总入口（`docs/README.md`）开头写明「先按职责找文档，不按文件名猜位置」。
- 每个一级目录 README = 二级路由 + 放置规则。
- 每份规范开头写 `## AI Quick Path`：本文回答什么问题、先读什么、最关键的 1–3 条约束。

## 通用层 → 项目层

规范分两层：**通用层**（跨项目可复用，留出占位项）和**项目层**（只写占位填充、现状、例外和本项目的坑）。项目层前 15 行写 `> 继承：` 并链接通用层；通用层前 20 行写 `> 项目落地：` 并链接各项目层。继承对登记在 `scripts/doclint/baseline.json` 的 `inherit_pairs`（新项目没有存量豁免时，这个文件可以只含这一个键），`doc-lint` 检查两端是否声明。不声明继承，Agent 从路由表跳进项目层后就不知道还有一份通用规范要读。

## 多个 Agent

只有**一个**入口文件（如 `AGENTS.md`）；其他 Agent 的入口文件（`CLAUDE.md` 等）只写转发：「规范以 AGENTS.md 为准，不在这里复制规则」。通用教训写进仓库，不留在某个 Agent 的个人记忆里。

## 交接文档是一次性路由

要把任务交给另一个 Agent 执行或审核时，写 `handoff.md`：先读什么（按顺序）、全局约束、每个任务的步骤与验证命令、**每次交审必须附的证据**、审核阻断清单。它就是给下一个 Agent 的定制路由表。
